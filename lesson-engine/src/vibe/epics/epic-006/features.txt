
# Epic-006 - Final Cleanup and GitHub Pages Deployment

## Overview

This epic focuses on cleaning up the application's existing interface, making several small usability improvements, and preparing the application for public deployment through GitHub Pages.

The epic includes:
- Replacing the global Options menu button with a Home button.
- Changing the Let's Spell category selection grid.
- Renaming SCSS colour variables to reflect their purpose.
- Adding animated transitions between pages.
- Changing the default Let's Spell selection mode.
- Increasing spacing between box colour labels and images.
- Configuring and performing the initial GitHub Pages deployment.

All changes must preserve existing activity functionality.

Follow the existing project architecture, design system and instructions in AGENTS.md.

## Feature-003 - Rename SCSS Colour Variables by Purpose

Status: complete
Notes: Central SCSS palette variables and the exposed default-theme custom properties now use theme-role names; every existing colour literal, opacity, gradient stop and animation remains unchanged, and all references were updated.

Refactor the application's existing SCSS colour variable names so that they describe the purpose of each colour rather than its actual appearance.

IMPORTANT:
I have manually adjusted some of the application's colours.

DO NOT modify, correct, replace or restore any current colour values.

This feature is a naming refactor only.

Requirements:

1. Semantic Variable Naming
- Rename colour variables so their names describe how they are used.
- Avoid including specific colour names such as orange, yellow, blue or teal where those names only describe the current value.
- Prefer naming based on theme, purpose and relative appearance.

Example:

Current:
$color-spell-orange

Preferred:
$color-spell-darker

The actual colour value assigned to the variable must remain exactly the same.

2. Gradient Colours
- Use consistent naming conventions for background gradient colours.
- Prefer names such as:
  - lighter
  - light
  - base
  - dark
  - darker
- Only use the number of variations actually required by the existing theme.
- Do not introduce unnecessary new variables.
- Ensure the new names correctly represent the existing colours' roles.

3. Theme Consistency
Apply the naming approach to all relevant themes, including:
- The default application theme.
- Let's Spell.
- Let's Find.
- Any other existing theme-specific colours.

4. Other Colour Variables
- Review other SCSS colour variables for names that are unnecessarily tied to their current colour values.
- Where appropriate, rename them to reflect their purpose.

Examples of useful semantic names:
- text-primary
- text-secondary
- background-primary
- border
- glass-background
- button-primary
- hover
- focus

- Follow the project's existing SCSS naming conventions.
- Avoid creating duplicate variables unnecessarily.

5. Preserve Existing Values
- Do not change hexadecimal values.
- Do not change RGB or RGBA values.
- Do not change HSL values.
- Do not change opacity.
- Do not change gradient stops.
- Do not change colour contrast intentionally.
- Do not alter the visual appearance of any page.

6. Update References
- Update every reference to renamed variables.
- Check SCSS files, mixins, component styles and theme definitions.
- Update any dependent CSS custom properties where appropriate.
- Ensure no references remain to removed variable names.
- Preserve the existing centralised theme structure.

7. Preserve Animation
- Do not change the animated background's movement.
- Do not change animation speed.
- Do not change gradient positioning.
- Do not change the existing background artefact fixes.

8. Verification
- Compare the application before and after the refactor.
- Confirm that colours remain visually identical.
- Check that every existing theme still works.
- Verify that all SCSS compiles successfully.
- Confirm that no undefined variable errors are introduced.

Acceptance Criteria:
- Colour variables use meaningful, purpose-based names.
- Variable names are no longer unnecessarily tied to specific colours.
- Every existing colour value remains unchanged.
- All references are updated.
- Gradients and glass effects look identical to before.
- All themes continue working.
- The SCSS builds successfully.
- No visual changes are introduced by this refactor.
