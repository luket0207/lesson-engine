## Bug-004 - Prevent Consecutive Repetition of Object Hiding Position

Status: complete
Notes: Stored each round's correct horizontal position and made the central generator exclude that position from the next equal-box-count round before its uniform random selection. The prior position is resolved independently of regenerated box colours and IDs, resets when box count changes, and is validated against the mapped correct box.

Currently, when Play Again is selected, the object can be hidden beneath a box in the same horizontal position as the previous game.

For example, when playing with three boxes, the object might be hidden beneath the left box three times in a row.

Although this is technically possible through random selection, it makes the game appear repetitive or broken.

Requirements:

1. Prevent Consecutive Position Repetition
- When Play Again is selected, the object must not be hidden beneath a box occupying the same horizontal position as the previous game.
- The correct box must always occupy a different position from the previous round.
- This restriction applies regardless of the box's colour.
- Compare the actual box position or index, not its colour or unique identifier.
- For example, if the object was hidden beneath the leftmost box, the next game must use a different position.
- The restriction should work with 2, 3 or 4 boxes.

2. Random Position Selection
- Continue selecting the correct hiding position randomly.
- Exclude the previous game's correct position from the available positions.
- Randomly select from the remaining valid positions.
- Do not simply alternate between fixed positions unless only two boxes are available.
- Every eligible position should have an equal chance of being selected.

Examples:

With 3 boxes:
Previous position: Left
Next position: Middle or Right

With 4 boxes:
Previous position: Second
Next position: First, Third or Fourth

With 2 boxes:
Previous position: Left
Next position: Right

3. Previous Game Tracking
- Store the previous game's correct box position.
- Preserve this information when Play Again is selected.
- Pass the previous position into the existing central game-generation utility.
- Generate the new correct position before assigning the object to its box.
- Map the selected position to the correct box's unique identifier.
- Do not confuse the previous box identifier with its position, as box identifiers and colours are regenerated each round.
- Do not reset the previous position before generating the next game.

4. New Games
- When starting Boxes mode for the first time, allow any valid hiding position.
- The position restriction applies when a previous round exists with the same number of boxes.
- If the number of boxes changes, reset the previous position restriction and allow all positions.
- Do not make the game predictable beyond preventing immediate repetition.

5. Preserve Existing Randomisation
- Continue generating a new random object for every round.
- Continue preventing the same object from appearing in consecutive rounds within the same category.
- Continue generating new box colours and arrangements.
- Continue generating a new random object entrance position.
- Do not change the existing box animations or object movement.
- Preserve all settings when Play Again is selected.

6. Implementation
- Update the existing game-generation utility rather than adding position-selection logic directly to the React components.
- Use the previous correct position as an optional input.
- Filter that position out of the available choices before making the random selection.
- Ensure the logic remains reusable and independently testable.
- Do not regenerate random values during ordinary component re-renders.

Acceptance Criteria:
- Play Again never places the object in the same horizontal box position as the immediately previous round.
- The restriction works correctly with 2, 3 and 4 boxes.
- Box colour changes do not affect position comparison.
