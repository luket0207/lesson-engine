## Bug-001 - Two-Column Options Layout and Auto Count Default

Status: complete
Notes: Reworked the options panel into a compact two-column, two-row grid with a narrow-screen single-column fallback, reduced page-specific spacing, and enabled Auto Count by default while retaining Normal speed and all other defaults.

The options panel on the Let's Count start screen currently takes up too much vertical space.

Requirements:
- Change the options panel to use a two-column grid layout.
- Arrange the four main settings into two rows and two columns.
- Ensure the layout is compact and well-balanced.
- Keep consistent spacing and alignment between options.
- The Auto Count speed buttons should remain within the Auto Count section when enabled.
- Reduce unnecessary vertical padding or gaps where appropriate.
- The Start Counting button, options panel and Back to Home link should ideally all fit within one viewport without scrolling.
- Maintain a usable layout on smaller screens without clipping or overlapping elements.
- Use responsive font sizes and spacing where necessary.
- Avoid introducing horizontal scrolling.
- Change Auto Count to be enabled by default.
- Normal should remain the default Auto Count speed.
- Users must still be able to disable Auto Count and use manual counting.
- Preserve all other existing option defaults.

Acceptance Criteria:
- The options panel displays two columns.
- Options are arranged clearly and consistently.
- The start screen fits vertically within the viewport at supported screen sizes where practical.
- No controls are clipped or inaccessible on smaller screens.
- Auto Count is enabled by default.
- Normal remains the default speed.
- All other options continue functioning correctly.

However, when the two navigation buttons fade in beneath it, the Finished! text moves upwards.

- The text should remain horizontally and vertically centred in its designated position.
- When the navigation buttons appear, they must not affect the position of the Finished! text.
- Reserve space for the buttons before they become visible, or position them independently of the Finished! text.
- The buttons should fade in beneath the text without causing any existing elements to move.
- Do not alter the existing Finished! entrance animation.
- Do not change the existing button fade-in timing.
- Keep the completion screen responsive.
- Ensure buttons never overlap the Finished! text on smaller screens.
- Avoid layout shifts caused by conditional rendering or changes to container alignment.

Acceptance Criteria:
- Finished! remains stationary after completing its entrance animation.
- The appearance of the buttons does not move the text.
- Buttons fade in smoothly beneath Finished!.
- No visible layout shift occurs.
- The layout remains correct on mobile, desktop and television screens.
- Existing completion animations and navigation continue working.
