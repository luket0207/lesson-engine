
# Epic-002 - Let's Count Activity

## Overview

Implement the Let's Count activity, allowing children to count upwards or downwards between 1 and a selected number.

The activity must support:
- Counting upwards or downwards.
- Counting to or from 5, 10 or 20.
- Manual or automatic progression.
- Configurable automatic counting speeds.
- Optional English number words.
- Animated introduction and completion screens.
- Animated numbers and words.
- A separate optional cartoon wobble effect.

All styling must follow the existing application design established in Epic-001.

Use existing global SCSS variables, fonts, glass styles, animations and shared components wherever possible.

The activity route is:
/letsCount

No separate teacher setup page is required.

## Feature-003 - Counting Sequence and State Management

Status: complete
Notes: Added reusable sequence and number-word utilities plus a guarded reducer hook that snapshots options and controls the full introduction, number, and finished lifecycle without timers or duplicate transitions.

Implement the underlying logic responsible for generating and controlling the counting sequence.

This feature should focus on counting logic and state management rather than visual animations.

Requirements:

1. Sequence Generation
- Generate a counting sequence using the selected direction and number limit.
- Count Up should start at 1 and finish at the selected number.
- Count Down should start at the selected number and finish at 1.
- Support the number limits 5, 10 and 20.
- Include both the starting and ending numbers.

Examples:
- Count Up, 5: 1, 2, 3, 4, 5.
- Count Up, 10: 1 through 10.
- Count Down, 5: 5, 4, 3, 2, 1.
- Count Down, 20: 20 through 1.

2. Number Words
- Provide English word equivalents for numbers 1 through 20.
- Use standard English spelling.
- Use capitalised words such as:
  - 1 = One
  - 2 = Two
  - 3 = Three
  - 10 = Ten
  - 20 = Twenty
- Keep number-to-word mapping in a reusable utility or data file.
- Only display words when the Words option is enabled.

3. Sequence States
Implement a clear sequence lifecycle.

Suggested states:
- Options
- Introduction Entering
- Introduction Holding
- Introduction Exiting
- Number Entering
- Number Displayed
- Number Exiting
- Finished Entering
- Finished Displayed

Use a consistent state machine or equivalent controlled sequence to prevent conflicting transitions.

4. Starting the Sequence
- Clicking Start Counting begins a new sequence.
- Capture the currently selected configuration.
- Reset the current number to the first number in the generated sequence.
- Display the introduction before displaying any number.
- Do not permit multiple sequences to start simultaneously.

5. Progression
- Display one number at a time.
- Advance through the generated sequence in the correct order.
- Never skip numbers.
- Never display two numerical digits simultaneously.
- The previous digit must fully exit before the next digit enters.
- Do not accept additional progression requests while a transition is running.

6. Completion
- Once the final number has completed its display and exit, transition to the completion screen.
- Do not loop automatically.
- Do not start another sequence without returning to the options screen.

7. Reliability
- Avoid stale timers and conflicting animation callbacks.
- Clean up active timers and listeners when leaving the activity.
- Prevent duplicate transitions from rapid clicking.
- Ensure the sequence behaves correctly when options are changed before starting.
- Use reusable logic where appropriate.

Acceptance Criteria:
- All six direction/number-limit combinations work.
- Numbers appear in the correct order.
- No numbers are duplicated or skipped.
- Words map correctly to their numerical digits.
- The final number completes before the Finished state.
- Repeated input cannot corrupt the sequence.
- Sequence state is cleaned up when the activity is exited.

8. Reusability

Acceptance Criteria:

## Feature-005 - Number and Word Animations

Status: complete
Notes: Added a full-viewport fixed counting layout with responsive digit/word regions, direction-aware 0.5-second slide-and-scale animations, synchronized word growth/fade, reduced-motion handling, and animation-completion lifecycle updates without the optional wobble.

Implement the main counting animations.

Requirements:

1. Counting Display Layout
- The counting animation should occupy the full available viewport.
- The number and optional word must be horizontally and vertically centred.
- Use DynaPuff for both numerical digits and number words.
- Use the application's existing white text colour.
- Do not allow scrolling during the counting sequence.

2. Digit Size
- The numerical digit should be extremely large.
- When Words is disabled, target approximately 80% of the viewport height for the digit.
- When Words is enabled, the digit should occupy the remaining available vertical space after allowing room for the word and appropriate padding.
- Digit sizing must adapt to different screen dimensions.
- Digits must not overflow or become clipped at their final position.
- Multi-digit numbers must fit horizontally within the viewport.

3. Word Size
- When Words is enabled, display the English word beneath the digit.
- Target word font size: 10rem.
- Reduce the size responsively where required to avoid overflow.
- Keep appropriate padding above, below and between the elements.
- Words must be centred horizontally.
- Words should not appear when the option is disabled.

4. Fixed Layout Areas
- Reserve fixed layout regions for the digit and word.
- Animations must not change the dimensions of these layout regions.
- The numerical digit must not jump vertically when its word animates.
- Changing between single-digit and double-digit numbers must not shift the overall layout.
- Animation movement should use transforms rather than layout-changing properties where possible.

5. Count Up - Entrance
When counting upwards:
- The digit begins outside the left edge of the screen.
- Its initial scale is 50% of its final size.
- It slides horizontally towards the centre.
- It grows from 50% to 100% while moving.
- It comes to rest in the centre of the digit's allocated area.
- Entrance duration: 0.5 seconds.

6. Count Up - Exit
When counting upwards:
- The digit slides from the centre towards the right.
- It shrinks from 100% to 50% while moving.
- It must finish completely outside the visible screen.
- Exit duration: 0.5 seconds.
- The next digit must not start entering until the previous digit has fully exited.

7. Count Down - Entrance
When counting down:
- The digit begins outside the right edge of the screen.
- Its initial scale is 50%.
- It slides towards the centre.
- It grows from 50% to 100%.
- Entrance duration: 0.5 seconds.

8. Count Down - Exit
When counting down:
- The digit slides towards the left.
- It shrinks from 100% to 50%.
- It must finish completely outside the visible screen.
- Exit duration: 0.5 seconds.
- The next digit starts only after the previous digit has exited.

9. Word Entrance
- Words must not slide horizontally.
- Words should grow from their centre point.
- The word animation begins at the same time as the digit entrance.
- The word should reach its full size at exactly the same time as the digit reaches the centre.
- Entrance duration: 0.5 seconds.

10. Word Exit
- Words should remain in their reserved display area.
- Words must not slide horizontally.
- When the digit exits, the word should shrink or fade out.
- The word exit must finish at the same time as the digit exit.
- Exit duration: 0.5 seconds.
- The previous word must not remain visible when the next number enters.

11. Animation Quality
- Animations should be smooth and fluid.
- Use CSS transforms and opacity where possible.
- Avoid layout shifts.
- Use appropriate easing functions.
- Do not add the cartoon wobble effect in this feature.
- That effect belongs exclusively to Feature-007.

12. Responsiveness
- Support mobile, tablet, desktop and television layouts.
- Account for narrow screens and landscape orientation.
- Make sure the largest digit and word combinations fit within the viewport.
- Use responsive sizing without changing the intended visual hierarchy.
- Respect prefers-reduced-motion.

Acceptance Criteria:
- Count Up digits enter from the left and exit right.
- Count Down digits enter from the right and exit left.
- Digits grow from 50% on entrance.
- Digits shrink to 50% on exit.
- Every entrance and exit lasts 0.5 seconds under normal motion settings.
- Words grow from their centre point.
- Words and digits finish entering simultaneously.
- Words never slide horizontally.
- Previous content fully exits before new content enters.
- No vertical layout shifting occurs.
- Digits and words remain centred and fit the viewport.
- No cartoon wobble has been implemented yet.


## Feature-006 - Automatic and Manual Counting Controls

Status: complete
Notes: Added centralized 4/2/1-second automatic delays with cleanup-safe display timers, plus a focused full-screen native manual control supporting click, touch, Enter, Space, and TV confirmation only while a number is fully displayed.

Implement the progression controls used during the counting sequence.

Requirements:

1. Automatic Counting
When Auto Count is enabled:
- Automatically advance to the next number after the selected delay.
- The delay begins only after the number's entrance animation has fully completed.
- The entrance animation must never count towards the display duration.
- The automatic delay must not begin during the previous number's exit.
- Each number should remain fully visible for the specified duration.

2. Automatic Speeds
Use the following durations:

Slow:
- 4 seconds.

Normal:
- 2 seconds.

Fast:
- 1 second.

These delays are additional to the 0.5-second entrance and exit animations.

3. Automatic Timing Example
For Normal speed:

- Number enters: 0.5 seconds.
- Number remains stationary: 2 seconds.
- Number exits: 0.5 seconds.
- Next number begins entering immediately after the previous number exits.

The same timing rules apply to every number, including the final number.

4. Manual Counting
When Auto Count is disabled:
- Do not automatically advance.
- After a number has completed its entrance animation, wait for user interaction.
- Clicking or tapping anywhere on the counting screen should advance to the next number.
- The click initiates the exit animation for the current number.
- After the exit animation completes, automatically begin the next number's entrance.
- Continue waiting for the next user interaction after that entrance completes.

5. Input Restrictions
- Do not allow manual advancement during the introduction.
- Do not allow advancement during number entrance animations.
- Do not allow advancement during number exit animations.
- Do not queue clicks made during animations.
- Rapid repeated clicking must not skip numbers.
- After the final number, the next valid advancement should trigger its exit and then the Finished! screen.

6. Keyboard and TV Remote Compatibility
- Support Enter and Space as manual advancement controls.
- Support standard TV remote confirmation keys when they generate normal Enter or click events.
- Manual progression must work without a mouse or touchscreen.
- Ensure the counting screen can receive the required keyboard input.
- Make the interactive counting area keyboard accessible with an appropriate accessible name.
- Avoid duplicate progression when one key press generates multiple browser events.
- Do not interfere with navigation buttons or unrelated controls.

7. Automatic Mode Interaction
- When Auto Count is enabled, the configured timer controls progression.
- Clicking the screen must not skip numbers in automatic mode.
- Automatic progression must stop when leaving the activity.
- Automatic timers must be cleaned up when the component is unmounted.

8. Timing Management
- Keep animation durations and speed settings in central constants.
- Coordinate state changes with completed animations.
- Avoid relying on multiple independent timers that can cause desynchronisation.
- Ensure delays start only after the relevant animations finish.
- Prevent duplicate transitions and stale callbacks.

Acceptance Criteria:
- Slow displays each number for 4 seconds after entrance.
- Normal displays each number for 2 seconds after entrance.
- Fast displays each number for 1 second after entrance.
- Each entrance and exit adds 0.5 seconds.
- Manual mode never advances without valid user input.
- Clicking anywhere on the counting display advances in manual mode.
- Enter and Space work in manual mode.
- Rapid clicking cannot skip numbers.
- Automatic mode does not respond to manual advancement.
- The final number follows the same progression rules.
- All timers are properly cleaned up.

Status: complete

Add a subtle cartoon-style wobble to numerical digits as they complete their entrance animation.

IMPORTANT:
This feature must be implemented independently from Feature-005.

It may be rolled back in the future without changing any of the main counting animations.

Requirements:

1. Wobble Effect
- Add a small wobble to numerical digits as they arrive at the centre of the screen.
- The effect should resemble a cartoon character coming to a sudden stop.
- Use a slight overshoot, rotation or squash-and-stretch effect.
- The effect should have personality without becoming overly distracting.
- Keep the wobble subtle enough that digits remain easy to read.

2. Animation Timing
- The wobble should occur at the end of the 0.5-second entrance animation.
- It must not introduce additional waiting time before the number is considered fully displayed.
- The wobble should be integrated into the existing 0.5-second entrance duration.
- Do not change the automatic counting delays.
- Do not change the exit animation duration.

3. Direction
- The wobble may respond to the entrance direction.
- Count Up digits enter from the left.
- Count Down digits enter from the right.
- Consider a small directional overshoot before settling into the centre.

4. Word Behaviour
- Apply the wobble to numerical digits only.
- Number words should retain their normal grow animation.
- The word must still reach full size at the same time as the digit finishes entering.

5. Isolation
- Implement the wobble as an optional animation modifier, separate keyframe definition or similarly isolated mechanism.
- Do not rewrite the underlying slide animation unnecessarily.
- The original slide-and-scale animation must remain functional without the wobble.
- Removing or disabling this feature must not affect the counting sequence, animation timings or layout.
- Respect prefers-reduced-motion.

Acceptance Criteria:
- Digits have a subtle cartoon wobble as they arrive.
- The wobble does not make the numbers difficult to read.
- The complete entrance still lasts 0.5 seconds.
- Words do not wobble.
- Automatic and manual timings are unaffected.
- The wobble can be removed independently without breaking Feature-005.
