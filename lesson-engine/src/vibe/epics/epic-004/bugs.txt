
# Epic-004 - Bugs

## Bug-001 - Allow Screen Click to Activate Next

Status: complete
Notes: Routed playback-surface forward input to Next when a non-final completion state is visible, while leaving final navigation inert and preserving button event filtering. Added a short reducer-backed, cleanup-safe item transition lock so rapid follow-up input cannot reveal the next item's image.

Currently, when the "Next" button appears after completing a word in a multi-item sequence, the user must click the button itself to advance to the next item.

The user should also be able to click anywhere on the activity screen to advance.

Requirements:
- When the "Next" button is visible, clicking anywhere on the activity screen should trigger the same action as clicking Next.
- The Next button itself must continue working normally.
- Pressing the Right Arrow key should also activate Next.
- Clicking or tapping the screen should move to the next item in the existing sequence.
- The next item must begin at the blank initial stage, requiring another click to reveal its image.
- A single click must never both advance to the next item and reveal its image.
- Prevent event bubbling from causing the Next button to trigger twice.
- Ignore additional clicks while transitioning between items.
- Preserve the existing playback order.
- Do not change the behaviour of the final item, where "Back to Category" and "Back to Home" buttons are displayed.
- When the final navigation buttons are visible, clicking elsewhere on the screen should not trigger navigation.
- Clicking the global menu or interacting with its modal must not activate Next.
- Preserve existing backward navigation. Pressing Left Arrow or right-clicking should still hide the Next button and return to the fully revealed word.

Acceptance Criteria:
- Clicking Next advances to the next item.
- Clicking anywhere on the activity screen while Next is visible also advances to the next item.
- Right Arrow activates Next.
- Only one item transition occurs per interaction.
- The next item starts with a blank screen.
- Global menu interactions do not trigger Next.
- Final-item navigation behaviour remains unchanged.
- Backward navigation continues working correctly.


## Bug-002 - Disable Text Selection Throughout the Application

Status: complete
Notes: Disabled text selection globally in the central stylesheet with browser-prefixed user-select rules, while restoring normal selection for inputs, textareas, and enabled contenteditable regions (including their descendants). Existing control interaction, focus, navigation, and animation behavior is unchanged.

Currently, text throughout the application can be highlighted and selected by clicking and dragging across it.

This causes the browser's default blue text-selection background to appear, which is undesirable for an interactive children's learning application.

Requirements:
- Disable text selection throughout the entire application.
- Users should not be able to highlight text by clicking and dragging.
- Prevent the default blue selection highlight from appearing.
- Apply this behaviour to headings, paragraphs, buttons, navigation pods, labels, animated letters and all other non-editable text.
- Ensure this also applies to the Let's Count and Let's Spell activities.
- Apply the styling globally through the central SCSS rather than modifying individual components.
- Use the CSS user-select property with a value of none.
- Include the appropriate vendor-prefixed properties where necessary for browser compatibility.
- Ensure the styling works across desktop, mobile, tablet and television browsers.
- Do not interfere with normal button clicks, navigation, hover effects or animations.
- Do not disable keyboard focus or accessibility features.
- If editable text fields, textareas or contenteditable elements are introduced, they must retain normal text selection and editing functionality.
- Do not prevent users from interacting with checkboxes or other form controls.

Acceptance Criteria:
- Text cannot be highlighted by clicking and dragging.
- The browser's blue selection background no longer appears.
- Text selection is disabled consistently across all application pages.
- All existing buttons, navigation and animations continue working.
- Keyboard and TV remote navigation remain unaffected.
- Editable text fields retain normal selection behaviour.
- The solution is implemented centrally and applies automatically to future pages and components.
