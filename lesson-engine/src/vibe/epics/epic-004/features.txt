
# Epic-004 - Let's Spell Activity

## Overview

Implement the Let's Spell activity.

The purpose of this activity is to help children learn how to spell English words by displaying an image and revealing the corresponding word one letter at a time.

The activity will contain four categories:
- Animals
- Food
- Sports
- Clothes

Each category contains 10 items.

Users can:
- Select an individual item.
- Play through all items in a category.
- Play through 3 randomly selected items.
- Play through 5 randomly selected items.
- Shuffle the order of all items.
- Move forwards and backwards through spelling stages.
- Navigate between items after completing each word.

All progression is manual. There is no automatic progression mode.

The activity will introduce a new orange and dark yellow colour theme while retaining the application's existing animated gradient, glass styling and shared components.

The Let's Spell activity should remain separate from the Let's Count activity.

Existing application functionality must be preserved.

## Feature-005 - Spelling Sequence and Stage Management

Status: complete
Notes: Added a reusable reducer-based spelling sequence hook that stores category, playback mode, ordered items, item index, reveal stage, completion visibility and animation lock state. It supports space-aware stages, guarded forward/backward progression and explicit blank-state item changes, plus a validated dedicated playback route that redirects malformed or missing sessions safely.

Implement the underlying sequence and progression logic for Let's Spell.

This feature should focus on state management and stage progression, independently of the visual animations.

Requirements:

1. Playback Modes

Support the following playback types:
- All items in category.
- 3 random items.
- 5 random items.
- One individually selected item.

2. Sequence State

- The selected category.
- The chosen playback mode.
- The ordered list of items.
- The current item index.
- The current reveal stage.
- Whether completion navigation buttons are visible.
- Whether a stage animation is currently running.

3. Reveal Stages

Every item follows this sequence:

Stage 0:
Blank screen.

Stage 1:
Image visible.

Stage 2:
Image and first letter visible.

Stage 3:
Image and first two letters visible.

Continue until every letter is visible.

Final letter stage:
Image and complete word visible.

Next stage:
Display navigation buttons beneath the complete word.

4. Multiword Items

- Support words containing spaces, such as Ping Pong.
- Spaces must not be treated as animated letters.
- Spaces should remain represented in the word layout.
- Progression must count actual letters rather than spaces.
- Do not require an extra click to reveal a space.
- Maintain the correct word spacing throughout the animation.

5. Forward Progression

- Each valid forward action reveals exactly one new stage.
- Do not skip stages.
- Do not allow multiple stages to advance from a single click.
- Ignore or safely prevent additional progression requests while a transition is running.
- Do not queue rapid clicks made during animations.

6. Backward Progression

- Allow the current sequence to move backwards by one reveal stage.
- If completion buttons are visible, moving backwards should first hide those buttons.
- Further backward actions should hide the most recently revealed letter.
- Continue backwards until only the image remains.
- One further backward action should return to the blank stage.
- At the blank stage, further backward actions should do nothing.
- Backward progression must not change the current selected item.
- Moving backwards must not automatically navigate to a previous item.

7. Item Progression

- After completing an item in a multi-item sequence, the user must explicitly select Next.
- Next loads the following item.
- Each new item starts from the blank stage.
- Never automatically advance to the next item.
- Individual item mode has no Next button.

8. Animation Coordination

- Do not allow progression during a running animation.
- Ensure stage transitions finish before accepting another input.
- Never display letters from different items simultaneously.
- Reset reveal state when moving to the next item.
- Clean up any pending animation callbacks when navigating away.

9. Routing and State

- Keep category and activity state clearly separated.
- Use a dedicated spelling playback screen or component.
- A route such as /letsSpell/:category/play may be used.
- Preserve the existing /letsSpell/setup route.
- If a playback route is opened without valid sequence data, safely return to the category selection page rather than displaying a broken screen.

10. Reusability

- Separate spelling sequence logic from animation components.
- Use a reusable hook, state machine or equivalent architecture.
- Keep the logic easy to test.
- Do not hardcode behaviour for individual words.

Acceptance Criteria:
- All playback modes generate the correct sequence.
- Every item starts with a blank screen.
- Image and letters are revealed in the correct order.
- Each forward action advances one stage.
- Each backward action reverses one stage.
- Spaces do not require extra clicks.

- Sequence logic is independent of visual animations.

- Return to the fully revealed word stage.
- The word and image must remain unchanged.
- Another backward action should then reverse the final letter as normal.

8. Responsive Layout

- Keep completion buttons beneath the word.
- Use a horizontal arrangement where sufficient width is available.
- Allow buttons to stack on smaller screens when necessary.
- Avoid clipping or horizontal overflow.
- Maintain a stable image and word position regardless of button visibility.

9. Navigation and Cleanup

- Navigating away must terminate the current playback session.
- Clean up timers, animation callbacks and event listeners.
- Returning to the category should restore the selection screen.
- Do not automatically restart the previous sequence.
- Keep category data and routes intact.

Acceptance Criteria:
- Completion buttons require one extra forward action.
- Next appears when more items remain.
- Next begins the following item at the blank stage.
- Final items display Back to Category and Back to Home.
- Individual selections never display Next.
- Buttons fade in smoothly.
- Revealing buttons never moves the image or word.
- Backward input hides completion controls first.
- All navigation routes work correctly.
- Activity state is cleaned up when leaving.
