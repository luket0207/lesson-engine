
# Epic-008 - Let's Spell Responsive Image Layout

## Overview

This epic addresses a longstanding responsive layout issue within the Let's Spell activity.

Currently, on smaller screens, some object images extend into the area containing the spelling word.

The word container overlaps the lower portion of these images, creating the appearance that the images are being cut off.

Several previous attempts to resolve this issue have failed, sometimes introducing additional problems with image positioning and desktop layouts.

This epic should provide a permanent solution by correcting the relationship between the image and word containers.

IMPORTANT:
The existing desktop layout looks correct and must remain visually unchanged.

The objective is to improve responsiveness without changing the existing visual design, gameplay or animations.

Follow all existing instructions in AGENTS.md.


## Feature-001 - Make Let's Spell Images Fit Above the Spelling Word

Status: complete

Implementation notes: Applied the viewport-derived upper-region height directly to every gameplay image, rather than only mobile images, and removed image-region paint clipping that concealed overflow. The existing grid rows, word/completion positions, aspect-ratio sizing, short-screen scrolling and image/letter animations remain unchanged.

### 1. Core Layout Requirement

In the Let's Spell gameplay screen, the object image must always appear entirely above the word being spelled.

The image should occupy the available space between:
- The top of the usable gameplay area.
- The top of the spelling word container.

Include appropriate padding at both ends.

The image must never overlap, cover or extend behind the spelling word container.

The word container must never obscure any portion of the image.

This requirement applies to every object image, regardless of its original dimensions or aspect ratio.

### 3. Investigate the Existing Overlap

Before changing any CSS, investigate why images are currently overlapping the spelling word container.

Inspect:
- The actual image element.
- The image wrapper.
- The parent gameplay container.
- The word container.
- The individual letter elements.
- All relevant ancestor containers.

Check for:
- Fixed heights.
- Minimum heights.
- Maximum heights.
- Overflow rules.
- Absolute positioning.
- Relative positioning offsets.
- Flexbox alignment.
- Grid alignment.
- Margins and padding.
- CSS transforms.
- Animation transforms.
- Stacking contexts.
- Conflicting responsive media queries.

Determine whether:
- The image is larger than its available layout area.
- The word container overlaps the image container.
- The image wrapper has an incorrect height.
- The image is being positioned too low.
- An ancestor is clipping the image.
- The word animation causes layout or stacking conflicts.

Fix the actual cause of the overlap.

Do not simply hide the problem with overflow clipping or z-index adjustments.


### 4. Establish a Proper Responsive Layout

On smaller screens, create a clear vertical relationship between the image and spelling word.

The layout should contain two primary regions:

IMAGE REGION
- Occupies the available space above the word.
- Uses the space remaining after accounting for the word region and necessary padding.
- Can shrink as the viewport becomes smaller.
- Contains the object image.
- Keeps the image horizontally centred.

WORD REGION
- Sits beneath the image region.
- Reserves sufficient space for the spelling text and its animations.
- Must not overlap the image region.
- Must remain visible throughout the activity.

Requirements:
- These regions must have separate layout boundaries.
- The word region must follow the image region vertically.
- The image region must not extend into the word region.
- The image and word must have a consistent minimum gap.
- The layout must respond automatically to changes in viewport dimensions.
- Revealing letters must not change the dimensions of either region.

Prefer CSS Grid or Flexbox using normal layout flow.

Avoid absolute positioning for the relationship between these two regions.

Do not introduce unnecessary additional wrappers.


### 5. Word Position Determines Available Image Space

This is the most important requirement of the epic.

The spelling word container must act as the lower boundary of the image display region.

The available image space should be determined by:

- The usable gameplay viewport height.
- The vertical position and required height of the word region.
- Top padding.
- Spacing between the image and word.
- Any existing required controls or safe-area padding.

The image must then fit within this remaining region.

Requirements:
- Reserve the necessary word region space first.
- Do not allow image dimensions to push the word below its intended position.
- Do not allow the image to overlap the word container.
- Shrink the image proportionally when available height decreases.
- Preserve the existing vertical placement of the word as closely as possible.
- Do not move the image downwards unnecessarily.

If the viewport is shorter, the image should become smaller.

The spacing between the image and word must remain consistent.


### 6. Scale the Actual Image Element

Responsive restrictions must apply to the actual rendered image, not merely its wrapper.

Requirements:
- Preserve each image's original aspect ratio.
- Scale width and height proportionally.
- Never stretch an image.
- Never crop an image.
- Never distort an image.
- Do not enlarge images beyond their original natural dimensions.
- Preserve the existing desktop maximum dimensions of 750px by 750px.
- Respect the available image container width.
- Respect the available image container height.
- Use the most restrictive dimension to determine the final image size.

Images should occupy as much of their available space as possible without exceeding their natural size or the existing maximum dimensions.

Ensure both width and height constraints are effective.

Do not rely on max-height: 100% unless the containing element has a properly constrained height.

Use appropriate sizing and layout rules to ensure the actual image fits.


### 7. Image Positioning

Images must appear naturally positioned within the space above the spelling word.

Requirements:
- Keep images horizontally centred.
- Position images within the available upper region.
- Maintain sensible top padding.
- Maintain clear bottom padding above the word.
- Avoid excessive empty space above images.
- Do not push images down towards the word.
- Do not add arbitrary large margins.
- Do not use translateY adjustments to compensate for incorrect layout sizing.

The image should look visually balanced within its available space.

On desktop, preserve the existing positioning exactly.


### 8. Prevent Word Container Overlap

The existing spelling animation container must not obscure images.

Requirements:
- Ensure the word container begins below the image's allocated region.
- Prevent any word container background or layer from covering image content.
- Remove unintended overlapping positioning.
- Correct any conflicting overflow rules.
- Ensure letter animation wrappers do not extend over the image at their resting positions.
- Preserve any necessary animation-specific clipping within the letter components themselves.

Do not use z-index alone as the solution.

The image and word containers must be genuinely separated in the layout.

The final visible bottom edge of the image must always remain above the top of the spelling region, with appropriate padding.

- The image must not move into the word region.
- If the entrance animation temporarily enlarges the image, ensure its animation remains visually contained without clipping or covering the spelling word.

Keep desktop animations visually unchanged.

### 13. Avoid Previous Failed Approaches

Previous attempts at resolving this issue introduced regressions.

Do not repeat the following mistakes:

- Simply reducing image width without constraining image height.
- Setting max-height percentages against an unconstrained parent.
- Moving images downwards with additional margins.
- Vertically centring images within the entire viewport without accounting for the word.
- Using z-index to conceal overlapping layout regions.
- Hiding oversized image content with overflow: hidden.
- Adding multiple conflicting CSS media queries.
- Changing global image styles.
- Repositioning desktop image containers.
- Changing desktop image sizes.
- Applying arbitrary pixel offsets instead of correcting container layout.

Review existing CSS before making changes.

Prefer a small, maintainable correction to the current layout structure.
